The AB-MCTS paper asks a simple question. You have a budget of LLM
calls, a task with a scoring function (unit tests, a validation
metric), and a model that can either produce a **fresh answer** or
**refine an existing one using feedback**. At every step, should you
go *wider* (sample another fresh answer) or *deeper* (refine one you
already have)?

Repeated sampling always goes wider. Sequential refinement always goes
deeper. Standard MCTS uses a fixed width, five children per expansion
in the paper's baseline. AB-MCTS decides at each node, using Bayesian
posteriors over scores and Thompson sampling.

From a categorical point of view, the paper rests on three structures:

1. The search tree is a **comonad**. Score backup reads *down* into a
   subtree, and expansion reads *up* along the path to the root.
2. Score backup is a **monoid homomorphism**. How much of the score
   history each method keeps (all of it, sufficient statistics, or
   just a visit count) is what tells the methods apart.
3. The GEN node is the **next element of an exchangeable sequence**,
   and AB-MCTS-M's mixed model is its de Finetti representation.

Like the earlier notes in this series, most of the categorical content
is about what gets *forgotten*, and when that forgetting costs nothing.

---

### 1. Wide, Deep, Fixed, Adaptive: Four Polynomial Functors

The paper's Figure 1 shows four tree shapes: purely wide, purely deep,
fixed width, and adaptive. Each is a tree type generated by a
**polynomial functor**. The polynomial says how many children a node
may have.

A finite tree whose nodes carry labels in $A$ (here, an answer and its
score), with branching described by a polynomial $F$, is an element of
the initial algebra

$$\mathsf{Tree}\_F(A) = \mu X.\; A \times F(X)$$

The four strategies differ only in $F$:

| Strategy | Polynomial $F$ | Shape |
|---|---|---|
| Sequential refinement | $1 + y$ | a single path: each node has 0 or 1 children |
| Standard MCTS (LATS config) | $1 + y^{5}$ | each node is a leaf or has exactly 5 children |
| Repeated sampling | $\sum\_{n} y^{n}$ at the root only, depth 1 | a single wide fan |
| **AB-MCTS** | $\mathsf{List} = \sum\_{n \in \mathbb{N}} y^{n}$ | any number of children, at any depth |

In $\mathbf{Poly}$ terms, $1 + y$ and $1 + y^5$ are sub-polynomials
of $\mathsf{List}$: they allow only some of $\mathsf{List}$'s arities.
Repeated sampling and sequential refinement are the two extreme
restrictions, and standard MCTS is a fixed restriction in between.
AB-MCTS uses all of $\mathsf{List}$ and leaves the arity at each node
to be chosen at runtime. In the language of polynomials, the
*position* of each node (its number of children) is no longer a
hyperparameter but a decision.

The paper's Appendix makes the same point less formally: repeated
sampling and sequential refinement are "special cases of a tree
search", and standard MCTS "naturally incorporates the two, while it
uses a fixed branching factor."

### 2. The Search Tree is a Comonad

Rose trees $\mathsf{Rose}(A) = \mu X.\, A \times \mathsf{List}(X)$
carry a **comonad** structure, which is the finite part of the cofree
comonad on $\mathsf{List}$:

* **extract** $\varepsilon : \mathsf{Rose}(A) \to A$ returns the root's
  label;
* **duplicate** $\delta : \mathsf{Rose}(A) \to
  \mathsf{Rose}(\mathsf{Rose}(A))$ relabels every node with *the
  subtree rooted there*.

The counit $\varepsilon$ is the "forget the context, keep the value"
map from §2.B of the note on *Scaling Discovery Requires Forgetting*.
The comonad's other operations describe how AB-MCTS actually computes.

#### A. Score backup reads down: co-Kleisli extension

Every per-node statistic the paper uses is computed from *the subtree
under that node*. AB-MCTS-M fits its mixed model at node $N$ using, for
each child $N\_j$, the scores in $T\_{\text{sub}}(N\_j)$, "the subtree
under $N\_j$, including $N\_j$ itself." A function that reads a whole
subtree and returns a value is a **co-Kleisli arrow**

$$k : \mathsf{Rose}(A) \to B$$

and **extend** applies it at every node at once:

$$k^{\dagger} = \mathsf{Rose}(k) \circ \delta : \mathsf{Rose}(A) \to \mathsf{Rose}(B)$$

Score backup maintains $k^{\dagger}$ incrementally. When a node is
added, only the statistics on its path to the root change, because
those are the only subtrees that contain the new node.

#### B. Expansion reads up: the path to the root

Expansion depends on context in the other direction. The paper's
refinement step

$$t^{k+1}\_{\rm out} = f\_{\rm LLM}\big(h\_{\rm refine}(\{t^{j}\_{\rm in}, t^{j}\_{\rm out}\}\_{j \le k})\big)$$

builds a prompt from earlier answers and their feedback. In the tree,
that history is the path from the root to $N$. So expansion is a
co-Kleisli arrow for a *different* context: a node together with its
ancestors, which is what a tree **zipper** captures.

One tree supports both readings: **backup looks at descendants, and
expansion looks at ancestors.** The paper's three-step loop (select,
expand, back up) alternates between the two.

### 3. The LLM is a Kleisli Arrow, and Every Node Has Infinitely Many Children

The LLM is stochastic: $f\_{\rm LLM}$ "may produce different outputs
$t\_{\rm out}$ for the same input $t\_{\rm in}$." That makes it a
**Kleisli arrow** for a probability monad $\mathcal{D}$:

$$f\_{\rm LLM} : \mathsf{Prompt} \to \mathcal{D}(\mathsf{Text}), \qquad R : \mathsf{Text} \to [0,1]$$

so the scored generator $\mathcal{D}(R) \circ f\_{\rm LLM}$ is a
kernel from prompts to score distributions.

Because each call is a fresh draw, a node's *potential* children are
not a finite list. They are an infinite stream of independent draws
from the same kernel, $\mathsf{Stream}(\mathsf{Text})$. The space of
all possible search trees is the **final coalgebra** of

$$X \;\mapsto\; A \times \mathsf{Stream}(X)$$

which has infinite width and infinite depth. The paper says the same
thing in operational terms: "the branching factor is theoretically
infinite."

A run of AB-MCTS **observes a finite subtree of this final
coalgebra**, closed under taking ancestors. Each LLM call reveals one
more node. In this picture:

* the **GEN node** at $N$ means "read the next element of $N$'s
  stream" (go wider);
* **selecting an existing child** means "go further into a part of
  the tree you have already revealed" (go deeper).

Standard MCTS reads exactly five elements of each stream and then
never returns to that node. AB-MCTS can always come back for more.

---

### 4. Backup is a Monoid Homomorphism, and the Methods Differ in What They Forget

What does a node actually *store*? The raw data is the **multiset of
scores** observed in its subtree, an element of the free commutative
monoid $\mathcal{M}(\mathbb{R})$ (finite multisets under union). Every
method maps this multiset to a summary, and in every case that map is
a **monoid homomorphism**: the summary of a union is computed from the
summaries of the parts. That property is what makes incremental
backup possible. Adding one new score updates the summary without
recomputing anything.

The methods differ in *which quotient* of $\mathcal{M}(\mathbb{R})$
they keep:

| Method | Stored summary | Homomorphism $\mathcal{M}(\mathbb{R}) \to S$ |
|---|---|---|
| Progressive widening | visit count $n$ | $\mathcal{M}(\mathbb{R}) \to (\mathbb{N}, +)$ |
| Standard MCTS / UCT | $(\sum r, n)$ | $\mathcal{M}(\mathbb{R}) \to (\mathbb{R} \times \mathbb{N}, +)$ |
| AB-MCTS-A (Beta) | $(\sum r\_n, \sum (1 - r\_n))$ | $\mathcal{M}(\mathbb{R}) \to (\mathbb{R}^2, +)$ |
| AB-MCTS-A (Gaussian) | $(N, \sum r\_n, \sum r\_n^2)$ | $\mathcal{M}(\mathbb{R}) \to (\mathbb{N} \times \mathbb{R}^2, +)$ |
| AB-MCTS-M | the multiset itself, per child group | the identity on $\mathcal{M}(\mathbb{R})$ |

Three observations follow.

**Conjugate priors forget losslessly.** For an exponential family, the
posterior after observing $r\_1, \dots, r\_N$ depends only on the
additive sufficient statistic $\sum\_n t(r\_n)$. The quotient map loses
information, but **the posterior factors through it**, so nothing the
decision depends on is lost. The Beta update in the appendix

$$\hat{\alpha} = \breve{\alpha} + \sum\_n r\_n, \qquad \hat{\beta} = \breve{\beta} + \sum\_n (1 - r\_n)$$

is a monoid action of $(\mathbb{R}^2, +)$ on the parameter space. This
is "forgetting that costs nothing", and it is why AB-MCTS-A is the
"more lightweight" variant.

**AB-MCTS-M keeps the free object.** The paper notes that "unlike
standard MCTS, AB-MCTS-M maintains individual scores rather than
averages." A mixed model fitted by MCMC has no finite sufficient
statistic that is shared across groups, so it keeps the multiset of
each group: the free commutative monoid, with nothing quotiented away.
It pays for this by refitting with MCMC at each node it selects
through.

**Progressive widening forgets the wrong thing.** The appendix
comparison with progressive widening is, categorically, an argument
about which quotient you choose. Progressive widening decides whether
to branch from $k n^{\alpha}$, a function of the visit count alone. It
**factors through $\mathcal{M}(\mathbb{R}) \to \mathbb{N}$**, the map
that throws away every reward. In the paper's words, "this decision
does not use important information gathered during the search, namely,
the observed rewards." AB-MCTS's branching decision factors through a
quotient that keeps the rewards.

A last structural bonus: all these monoids are **commutative**, so the
order in which backups arrive doesn't matter. That is the algebraic
reason Thompson sampling "has the advantage of allowing node expansion
in parallel". Results can arrive in any order and be merged into the
same summary.

### 5. Thompson Sampling: a Policy Defined on an Arm You Haven't Pulled

At node $N$ the available actions are

$$A\_N = \{a\_0\} + \{a\_1, \dots, a\_{n\_{\rm child}}\} \;\cong\; 1 + \mathsf{Children}(N)$$

which is the familiar **pointed set** $1 + X$. The extra point $a\_0$
is the GEN node, a formal placeholder for "a child that doesn't exist
yet."

**UCT can't handle this.** A UCT index is a deterministic map that
computes each arm's score from *that arm's own* statistics (its mean
and visit count). The GEN arm has no statistics, so the map is
undefined on the extra point. The paper: "GEN nodes do not have child
nodes, making it impossible to compute their UCT scores."

**Thompson sampling only needs a distribution per arm.** In a Markov
category it is the composite

$$1 \xrightarrow{\;\bigotimes\_{j} P\_N(r \mid a\_j)\;} \mathbb{R}^{A\_N} \xrightarrow{\;\arg\max\;} A\_N$$

a tensor product of independent posterior predictives followed by a
deterministic argmax, giving a Kleisli arrow $1 \to \mathcal{D}(A\_N)$.
To extend this to $1 + X$, you only have to supply a predictive
distribution for the extra point, and you don't need any observations
of it. The two AB-MCTS variants are two ways of supplying it.

---

### 6. AB-MCTS-M: The GEN Node is the Next Element of an Exchangeable Sequence

AB-MCTS-M's model at node $N$ is a two-level hierarchy:

$$\alpha\_j = \mu\_\alpha + \sigma\_\alpha \epsilon\_j, \qquad r\_{\tilde{N}} = \alpha\_j + \sigma\_y \epsilon\_{\tilde{N}}$$

with priors on $(\mu\_\alpha, \sigma\_\alpha, \sigma\_y)$. As a string
diagram in a Markov category, the hyperparameters
$\theta = (\mu\_\alpha, \sigma\_\alpha, \sigma\_y)$ are **copied** to
every group, each group draws its own intercept $\alpha\_j$, and each
group's scores are drawn given $\alpha\_j$.

Here is why the structure fits. The children of $N$ are independent
draws from the same kernel $f\_{\rm LLM}(t\_{\rm in}(N))$ (§3). So the
qualities $\alpha\_1, \alpha\_2, \dots$ of the subtrees they root form an
**exchangeable sequence**: their joint law doesn't change if you
reorder them. **De Finetti's theorem**, which has a purely categorical
proof in Markov categories (Fritz, Gonda, Perrone), says an
exchangeable sequence is a *mixture of i.i.d. sequences*: there is a
latent parameter, here $\theta$, such that conditional on $\theta$ the
$\alpha\_j$ are i.i.d.

In that reading, the GEN node's predictive is the **posterior
predictive for the next element $\alpha\_{n+1}$** of the exchangeable
sequence, marginalized over the posterior on $\theta$:

$$P\_N(r \mid a\_0) = \int P(r \mid \alpha\_0)\, P(\alpha\_0 \mid \theta)\, P(\theta \mid \text{data})\; d\alpha\_0 \, d\theta$$

This is the paper's sentence "the GEN node … is inferred not from the
prior alone but rather from the posterior distribution over
$\mu\_\alpha$ and $\sigma\_\alpha$, which is informed by the other
observed data", written as a composite of kernels. The existing
children never send scores *to* the GEN node, but they inform it
through the shared parameter $\theta$, the one wire in the diagram
that every group is connected to.

The exploration bonus also falls out of the structure. GEN's
predictive integrates over one more uncertain latent variable
($\alpha\_0$, which has no data) than any existing child does, so it is
wider. In the paper's words, "since `eps_j_gen` has no associated
observed data, `r_gen` typically exhibits higher variance." Thompson
sampling picks the wider distribution more often when its mean is
competitive, so going wider becomes the default whenever the existing
children look unremarkable.

(Exchangeability is what justifies the *hierarchical shape* of the
model. The *Gaussian* form of the levels is a separate modelling
choice that exchangeability doesn't decide.)

---

### 7. AB-MCTS-A: Factoring the Choice Through a Coproduct

AB-MCTS-A drops the shared parameter and changes the tree instead.
Every node's choice

$$1 + \mathsf{Children}(N)$$

is split into two steps: first choose **GEN** or **CONT** (a binary
choice, $1 + 1$), and if CONT, choose a child. All children are
"aggregated under a single CONT node."

This is the same move as the **hierarchical MoE** in the note on
*Outrageously Large Neural Networks*: a distribution over $1 + X$ is
factored into a distribution over which summand, followed by a
conditional distribution inside the chosen summand. That's a
disintegration, or Kleisli composition with the $\mathcal{D}$ monad.
The point of factoring is that each step now has its own observations:

* the **GEN** node at $N$ receives the scores of $N$'s *direct
  children*, i.e. how good fresh samples from $N$ have been;
* the **CONT** node at $N$ receives the scores of *deeper
  descendants*, i.e. how good refinements below $N$ have been.

The appendix walkthrough confirms this. At the root, the GEN
posterior is informed by $N\_1, N\_2, N\_3$ = $(0.8, 0.0, 0.2)$, while
CONT uses the deeper scores $(0.8, 1.0, 0.3)$. Categorically, this
splits the subtree's multiset along a coproduct:

$$\mathcal{M}(\text{children} + \text{deeper}) \;\cong\; \mathcal{M}(\text{children}) \times \mathcal{M}(\text{deeper})$$

($\mathcal{M}$ sends coproducts to products.) AB-MCTS-M gives GEN an
observation history by *sharing a latent parameter* across groups.
AB-MCTS-A gives it one by *rewiring the tree* so that GEN owns a
summand of the data. The paper's wording, "a clear path for score
propagation", describes this rewiring. Because the backup never
passes *through* another GEN node, each observation is credited to
exactly one GEN node.

### 8. SelectBest is a Different Monoid, and So is the Metric

After the budget is spent, the algorithm returns the best node.
`SelectBest` is a fold of the whole tree into the **max semilattice**
$([0,1], \max)$. That is another monoid homomorphism out of
$\mathcal{M}(\mathbb{R})$, but a very different one from the one that
*guides* the search.

The search guidance (§4) uses means and posteriors, which care about
the *typical* quality of a branch. The final answer only cares about
the *best* quality ever seen. Best-of-$n$ is the extreme case: there is
no guidance at all, only the max fold. That explains the paper's
ARC-AGI result, where repeated sampling ranks 1st at budget $2^7$
(15.0% / 18.6% Pass@2). When the objective is a max, a search that
goes very wide is already doing the right fold. AB-MCTS catches up and
pulls ahead only at larger budgets (up to $2^9 = 512$), once there is
enough data for the guidance to pay off.

The paper's Figure 5 axis, $\log(\text{mean depth} / \text{mean
width})$, is a functor from trees to $\mathbb{R}$ that forgets
everything except *shape*. It is useful for exactly that reason. It
shows the AB-MCTS variants landing between the pure-wide and pure-deep
extremes, and wider than standard MCTS.

### 9. What the Categorical View Does Not See

* **The evaluator is a proxy.** The search optimizes $R$ (public
  tests, a validation split), while the paper's final metric uses
  $R\_{\rm gt}$ (hidden tests). Nothing in the structure above relates
  the two. A homomorphism out of $\mathcal{M}(\mathbb{R})$ for $R$-scores
  says nothing about $R\_{\rm gt}$, and the paper names "a reliable
  score evaluator" as its main limitation.
* **Why LLM samples are diverse enough.** §3 treats a node's children
  as an i.i.d. stream, but whether that stream contains *good* answers
  is a property of the model and the task, not of the tree. Category
  theory doesn't explain why repeated sampling is a strong baseline;
  it only explains why AB-MCTS can reproduce it.
* **Cost beyond call counts.** The budget is counted in API calls. On
  MLE-Bench, evaluating a node means training a model on a GPU, a cost
  the paper flags as future work. The tree structure has no notion of
  per-node cost.
* **Gaussian scores on $[0,1]$.** AB-MCTS-M models pass rates in
  $[0,1]$ with Gaussians, and AB-MCTS-A (Beta) applies a Beta update
  to continuous scores rather than Bernoulli trials. The paper admits
  "usually this update rule is used in conjunction with the Bernoulli
  trial." These choices work in practice, but the categorical
  structure doesn't justify them.

The categorical reading explains **why the algorithm is well defined**
(a policy on $1 + X$, a GEN predictive with no direct data), **why it
is cheap to update** (monoid homomorphisms, order-independent
backups), and **why the two variants differ** (sharing a latent
parameter vs. factoring a coproduct). It does not explain why the
results come out as they do. Those numbers are empirical: average rank
2.3 for AB-MCTS-M against 3.5 for repeated sampling and 4.2 for
standard MCTS in Table 1, and 1.3 on MLE-Bench.

### Summary

| Paper construct | Categorical reading |
|---|---|
| Repeated sampling / sequential refinement / standard MCTS / AB-MCTS | Trees for sub-polynomials of $\mathsf{List}$: depth-1 fans, $1+y$, $1+y^5$, all of $\mathsf{List}$ |
| Search tree | The rose-tree comonad: extract the root, duplicate into subtrees |
| Score backup over $T\_{\text{sub}}(N\_j)$ | Co-Kleisli extension $\mathsf{Rose}(k) \circ \delta$ |
| Refinement from history | Context in the other direction: a zipper, the path to the root |
| $f\_{\rm LLM}$ at nonzero temperature | Kleisli arrow $\mathsf{Prompt} \to \mathcal{D}(\mathsf{Text})$ |
| "Theoretically infinite" branching | Final coalgebra of $X \mapsto A \times \mathsf{Stream}(X)$; a search reveals a finite subtree |
| GEN node | The extra point of $1 + \mathsf{Children}(N)$; "read the next element of the stream" |
| Stored node statistics | Monoid homomorphisms out of $\mathcal{M}(\mathbb{R})$ |
| Conjugate updates (AB-MCTS-A) | Lossless forgetting: the posterior factors through sufficient statistics |
| Individual score lists (AB-MCTS-M) | Keeping the free commutative monoid |
| Progressive widening's weakness | Branching that factors through the reward-forgetting count map |
| Parallel expansion | Commutativity of the backup monoid |
| Thompson sampling | $\bigotimes\_j$ predictives, then argmax: a Kleisli arrow $1 \to \mathcal{D}(A\_N)$ |
| UCT inapplicable to GEN | An index defined only on arms with data, not on the extra point |
| Mixed model's GEN predictive | De Finetti: the next element of an exchangeable sequence |
| CONT node | Factoring a choice over $1 + X$ through a coproduct (a disintegration) |
| SelectBest / best-of-$n$ | A fold into the max semilattice |
